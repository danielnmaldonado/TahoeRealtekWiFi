Application installation

The destination is /Applications on the running system. Copies in Downloads, Desktop, Release or ~/Applications are not updated by this installer.

Passwords and preferences

Saved Wi-Fi passwords in Keychain and application preferences are preserved. The app never saves the administrator password used by Installer.

An ad-hoc signed rebuild may require Keychain access approval again. This does not mean that the network password was deleted.

Service and login startup

After copying, the app opens as the logged-in user, not as root. Initial setup requests service and login-item registration. A previous explicit choice to disable these features is preserved.

macOS may still require approval in System Settings → General → Login Items & Extensions. This package does not bypass approval.

When upgrading a registered service, sign in to the account that registered it and quit the app before installing. A new 0.2.8 installation without a graphical session can be completed by opening the app after login. When packaging an older 0.2.5 binary, install with a graphical session or enable the service and login startup from the app menu afterward.

Adapters and kernel extension

USB adapters and support… distinguishes catalog entries, descriptor matches and a bound driver. Adapter catalog… shows all 250 profiles and their actual enablement status. Not every profile has an implemented driver. This package installs only the app; it does not update the kernel extension.

Signal diagnostics

Signal diagnostics… compares raw and filtered readings with connection and error counters. A zero reading means unavailable, not minimum signal. The bounded in-memory report contains no network names, addresses or passwords. Install the matching driver source build to apply the PHY-sample fixes.

Signing

A package built without Developer ID certificates is local, unsigned and not notarized. A .pkg does not remove signing or security requirements.
