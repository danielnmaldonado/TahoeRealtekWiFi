# Historical macOS and USB validation — build45/app40 (30/10/2026)

Base: complete build44/app39 source supplied by the user. This round
continues directly from that base. Versions: driver 0.13.20/build45,
app 0.2.14/build40.

## Fixes reproduced before the change

1. The actual attempt to load build44 failed to resolve
   `_thread_call_allocate_with_priority`. The local KDK identifies the function
   as a Private.kext export. The controller now uses the public
   `thread_call_allocate_with_options` function from the Mach KPI, preserving the callback,
   context, KERNEL priority and zero options. No private dependency
   was added. The regression compiles the actual expression against the public API.
2. With two adapters, the app list could confirm that the selected
   Registry ID had returned while keeping the token invalidated. All subsequent
   STATUS responses were discarded. The app renews the confirmed selection;
   the regression uses the actual AppKit disappearance and return flow.
3. `rtw-usb-match` found both USB devices but returned failure because it required
   exactly one result. It now accepts one or more and retains deduplication.
   Native regression covers zero, one, two and a duplicate profile.
4. RTL8192EU diagnostics required libusb even on macOS. They now use native
   IOKit for four bounded vendor-IN reads, targeting only 2357:0108
   and checking identity again before opening. They reject ambiguity,
   timeouts and truncated responses. The Linux path using libusb remains.

The package .command scripts have executable permission again. The
credential fixture was aligned with the app's actual initialization default
(auto-reconnect enabled), preserving tests that block late JOIN.

actual ad-hoc signatures were verified. All 14 native app suites
passed with ASan/UBSan. Native probe tests also passed with

TahoeRealtekWiFi.kext; no module was loaded and no RTW controller was
in IORegistry. Driver absence and the HAL tests above are separate

WPA2, DHCP, traffic and the two controllers' physical coexistence through the new

Passive tests do not certify performance, stability or 5 GHz station operation.
