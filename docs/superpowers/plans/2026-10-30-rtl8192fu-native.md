# Dedicated RTL8192FU station backend

The four verified FU catalog IDs need their own two-path 2.4GHz chip backend.
Reuse the host net80211 WPA2/CCMP/controlled-port protocol, never an EU/AU/8814
hardware identity. Pin and preserve Linux rtl8xxxu GPL-2.0-only source/notice.

1. RED typed bus/OTP/FW lifecycle tests, including wrong firmware/header/ROM,
   exact bounds, ambiguous failed writes, measured RFK failure and cleanup.
2. Import source-verified FU MAC/BB/AGC/RF/power/channel/IQK/LCK primitives and
   required common rtl8xxxu helpers through a checksum-pinned generator. Keep
   Linux register ordering; adapt only OS transport, bounded errors and real
   calibration readiness. Strict actual ROM values; no fabricated radio power.
3. Implement distinct 0x4000 paged 8051 image loading, real feature/ready report,
   LLT/USB queues, boot, final legacy/HT20/40 operating profile and H2C runtime.
4. Dedicated wire/RSSI/rate and controller adapter for actual typed FU context,
   DMA/FW/PHY/RFK before AUTH, final peer modes before RUN, host BA, software
   CCMP and port ownership. Publish exact parent controller hooks separately.
5. Run meaningful ASan/UBSan bus-failure and actual imported HT negotiation
   tests, checksum/determinism verification and native KDK compilation. No
   hardware calls/installations or physical throughput claims by this agent.
